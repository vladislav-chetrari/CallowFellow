# 09. UI и навигация

## Иерархия экранов

```
App (MaterialTheme)                          shared/src/task3/ui/App.kt
└── Root                                     shared/src/task3/ui/Root.kt
    ├── LlmScreen        (полноэкранный, если ui.showLlmScreen)
    ├── EmbedScreen      (полноэкранный, если ui.showEmbedScreen)
    └── Scaffold + NavigationBar
        ├── Tab.CHAT     → ChatTab
        ├── Tab.DOCS     → DocsTab
        └── Tab.SETTINGS → SettingsTab

Диалоги (AlertDialog), поднятые поверх любого экрана:
    ├── Диалог очистки чата   (ChatTab,     ui.showClearDialog)
    ├── Диалог пресета        (ChatTab,     ui.showPresetDialog)
    ├── Диалог статьи         (DocsTab,     ui.showWikiDialog)
    ├── Просмотр документа   (DocsTab,     ui.viewingSource != null)
    └── Диалог API-ключа      (Root,        ui.showKeyDialog)
```

Навигация — **одноэкранная**: вместо навигационного графа используются флаги в
`Task3UiState` (`showLlmScreen`, `showEmbedScreen`). Ни `navigation-compose`, ни
`ViewModel`-навигации в зависимостях нет.

## Три корневых таба

| Таб | Файл | Содержимое |
|---|---|---|
| Чат | `ChatTab.kt` | шапка с моделью и пресетом, статус движка, лента сообщений, поле ввода |
| Документы | `DocsTab.kt` | FAB «+», список документов, прогресс индексации, переключатель «В поиске», удаление, просмотр |
| Настройки | `SettingsTab.kt` | две строки-навигатора (LLM, Эмбеддинги) и подпись версии |

Нижняя навигация **скрывается при открытой клавиатуре**:

```kotlin
val imeVisible = WindowInsets.ime.getBottom(LocalDensity.current) > 0
// bottomBar = { if (!imeVisible) NavigationBar { … } }
```

Иначе `NavigationBar` перекрывал бы поле ввода.

## Экраны моделей

### `LlmScreen` — «Модель языка»

Две секции: **Локальные (on-device)** и **Облачные**.

Карточка локальной модели содержит:

* `RadioButton` — клик выбирает модель, если она скачана, иначе **запускает скачивание**
  (то есть радиокнопка совмещает выбор и загрузку);
* название и размер (`"${m.sizeMb} МБ"`, плюс `· скачана`, если файл на диске);
* один из четырёх блоков в зависимости от состояния:
  * идёт загрузка — `LinearProgressIndicator` + «Скачиваю: N%» либо «Скачиваю: N МБ…»,
    если сервер не отдал длину;
  * не скачана — кнопка «Скачать»;
  * скачана — кнопка «Удалить файл»;
  * для выбранной модели — статусная строка (`Загружена, готова` / `Загружаю…` /
    `Скачиваю: N%` / `Ошибка: …`).

Важная деталь: глобальный `Downloading` **чужой** модели не показывается —
если у этой карточки нет собственного `progress`, строка статуса для `Downloading`
возвращает `null` и не рисуется. Это защита от бага, когда индикатор загрузки
одной модели загорался на карточке другой.

Секция «Облачные» — одна карточка `DeepSeek Chat` с переключателем выбора,
подсказкой «API-ключ задан» / «Нужен API-ключ» и кнопками
«Ввести ключ» / «Сменить ключ» / «Убрать ключ». При выборе DeepSeek без ключа
сразу открывается диалог ввода.

### `EmbedScreen` — «Модель для эмбеддингов»

Устроена так же, с одной дополнительной строкой-предупреждением вверху:

> Смена модели очищает индекс документов — статьи придётся добавить заново.

В подписи модели показывается размерность (`"${m.sizeMb} МБ · dim ${m.dim}"`).
Значение `dim` — из каталога, для подписи; настоящая размерность узнаётся пробой
при загрузке движка.

| Диалог | Триггер | Содержимое | Результат |
|---|---|---|---|
| Очистить чат? | `IconButton` с иконкой `Delete` в шапке чата | предупреждение о необратимости | `ClearConfirmed` → `repo.clearChat()` |
| Пресет генерации | `IconButton` со `Star` | 3 радио-варианта с описанием и параметрами (`temp 0.5 • topK 40 • topP 0.9`) | `PresetSelected` → `repo.selectPreset()` |
| Статья из Википедии | FAB «+» на «Документах» | поле ввода с плейсхолдером `https://ru.wikipedia.org/wiki/…` | `WikiConfirmed` → `repo.addWikiDoc()` |
| Просмотр документа | тап по карточке документа | текст документа (до 3000 символов, скроллится) | `DocViewDismissed` |
| API-ключ DeepSeek | кнопка в `LlmScreen` или автооткрытие | поле с `PasswordVisualTransformation`, плейсхолдер `sk-...` | `KeySaved` → `repo.saveDeepSeekKey()` |

## Взаимодействие с системной «назад»

Вложенные экраны не закрывают приложение, а возвращают в настройки.

* **Android** — `OnBackPressedCallback` в `MainActivity`:
  `showLlmScreen` → `LlmScreenClosed`, `showEmbedScreen` → `EmbedScreenClosed`,
  иначе колбэк выключается (`isEnabled = false`) и передаётся системе.
* **Desktop** — `Window.onKeyEvent`, `Esc` делает то же самое.

## Взаимодействие с UI-системой Android

* Edge-to-edge: `enableEdgeToEdge()`.
* Светлый статус-бар и навигация:
  `isAppearanceLightStatusBars = true`, `isAppearanceLightNavigationBars = true`.
* Отступы: `Scaffold(modifier = Modifier.windowInsetsPadding(WindowInsets.safeDrawing), contentWindowInsets = WindowInsets(0, 0, 0, 0))`
  — двойная обработка insets исключена.
* Поле ввода: `Row(... .imePadding())`, `maxLines = 4`.
* Автопрокрутка к последнему сообщению через `LaunchedEffect(ui.messages.size)`.

## Отображение состояния движка

Единый блок для `EngineStatus` (и аналогичный для `EmbedState`):

| Состояние | Что видит пользователь |
|---|---|
| `Idle` / `Ready` | ничего, кроме подсказки `chatHint`, если модель не готова |
| `Downloading(p)` | «Скачиваю модель: p%» + индикатор |
| `LoadingModel` | «Загружаю модель…» + индикатор |
| `Generating` | «Генерирую…» + индикатор + кнопка «■» (отмена) |
| `Error(m)` | карточка «Ошибка: m» + кнопка «Повторить» |

`canChat` (можно ли вводить текст) вычисляется в ViewModel:

| Выбор модели | `canChat` | Подсказка |
|---|---|---|
| Не выбрана | `false` | «Выбери модель в Настройках» |
| DeepSeek, ключ пуст | `false` | «Введи API-ключ в Настройках» |
| DeepSeek, ключ есть | `true` | — |
| Локальная, файл не скачан | `false` | «Скачай модель в Настройках» |
| Локальная, файл скачан | `true` | — |

## Лента сообщений

* Роли подписаны как `Вы` и `Собеседник`.
* Пустой текст (идёт генерация) рисуется как курсор `▍`.
* Ключ элемента `messages` — `ChatMessage.id`, присваивается из счётчика `idSeq`
  в репозитории, поэтому стабилен при стриминге (текст меняется, id — нет).
* Сообщения об ошибке генерации попадают в ленту как обычный текст
  (`"Ошибка: …"`), а статус при этом становится `EngineStatus.Error`.

## Тема

Используется `MaterialTheme` **без параметров** — дефолтная палитра Material 3.
Явных `darkColorScheme`/`lightColorScheme`, шрифтов и размеров в проекте нет,
поэтому обе платформы выглядят одинаково и подчиняются системным настройкам.
