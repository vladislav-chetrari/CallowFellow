# 01. Обзор продукта

## Что это

**CallowFellow** — офлайн-чат-собеседник с локальной LLM и собственной базой знаний
(RAG). Модель и эмбеддинги скачиваются на устройство один раз и дальше работают
**без интернета и без облака**.

Версия: **0.1.0** (`gradle/libs.versions.toml` → `[versions].app`).
Пакеты приложения: `com.callowfellow` (Android), заголовок окна `CallowFellow` (Desktop).

Проект вынесен из «Недели 5» челленджа AI-Advent-Challenge в отдельный репозиторий;
при переносе переименовано только приложение, кодовая база (включая исторические
имена пакетов `task2.*` / `task3.*`) сохранена как есть — см.
[04. Структура проекта](04-struktura-proekta.md#историческое-наследие-task2--task3).

## Главная идея

| Режим | Что делает | Интернет |
|---|---|---|
| **Локальный LLM** | Qwen2.5-1.5B-Instruct (Q8) или Qwen3-0.6B (int4) генерируют ответ прямо на устройстве через LiteRT-LM | Не нужен (после скачивания модели) |
| **Облачный LLM** | DeepSeek Chat через Koog — для сравнения качества RAG | Нужен + API-ключ |

База знаний наполняется статьями Википедии: приложение скачивает текст, режет на
чанки, считает эмбеддинги локально и отвечает на вопросы **с ссылками на источники**.

## Пользовательские сценарии

1. **Скачать модель.** Экран «Настройки» → «Модель языка» → «Скачать». Прогресс в процентах
   (или в МБ, если сервер не отдал `Content-Length`).
2. **Задать вопрос по базе.** Вкладка «Документы» → FAB «+» → вставить ссылку
   `https://ru.wikipedia.org/wiki/…` или просто название статьи. Дождаться индексации.
3. **Спросить.** Вкладка «Чат» → вопрос → ответ с цифровыми ссылками `[1]`, `[2]`
   и блоком «Источники» в конце.
4. **Переключить пресет генерации** (иконка ★ в шапке чата): Точный / Баланс / Живой.
5. **Включить облако.** «Настройки» → «Модель языка» → DeepSeek Chat → ввести API-ключ.

## Основные возможности

### Чат

* **Полностью офлайн** после первого скачивания модели.
* **GPU-first генерация** с автоматическим откатом на CPU: при загрузке движка
  выполняется пробная микрогенерация, и если GPU-бэкенд не тянет (`Can not find OpenCL library`),
  движок пересоздаётся на CPU — до того, как пользователь увидит ошибку в чате.
* **Потоковый вывод** — дельты из нативного движка сразу попадают в UI.
* **Отмена генерации** — закрытие активной `Conversation` прерывает нативный декод.
* **Скользящее окно контекста** — последние 10 сообщений, что умещается в KV-кэш
  маленькой модели.
* **Долговременная память** — детерминированное извлечение фактов
  («Меня зовут Влад», «Я люблю кофе», «запомни: …») и их подстановка в системный промпт.
  Правила, а не LLM: маленькие модели игнорируют мета-инструкции вида «перечисли факты или
  ответь NO» (см. комментарий в `FactExtractor`).
* **Определение языка по диалогу** — язык не зашит в промпт, кроме фолбэка на русский.
* **Несколько чатов** — список диалогов в drawer'е (бургер в шапке чата):
  создание, переключение, переименование, удаление. У каждого чата своя история
  в БД, заголовок по умолчанию — первое сообщение, список отсортирован по активности.

### RAG

* **Источник документов** — статьи Википедии (`action=query&prop=extracts&explaintext=1`).
* **Структурный чанкинг** — статья → секции → абзацы, помеченные заголовком секции;
  длинные абзацы режутся только по границам предложений (никаких фиксированных окон
  и перекрытий — экономия памяти на телефоне).
* **Эмбеддинги** — EmbeddingGemma 270M (dim 768), CPU, батчами по 16, с переиспользованием
  векторов для неизменённых текстов.
* **Поиск** — brute-force косинус по всем чанкам активных документов.
* **Два гейта релевантности**: порог косинуса `MIN_SCORE = 0.55` и проверка пересечения
  корней слов. Без них запрос не по теме базы получал 5 мусорных чанков и вынужденный
  отказ «в документах этого нет».
* **Маршрутизация запросов** — small-talk («привет», «как дела», «thanks») обрабатывается
  без ретрива: экономит вызов EmbeddingGemma и не кормит модель мусорным контекстом.
* **Переключение вклада документа** — документ можно оставить в базе, но исключить из поиска.
* **Честные ссылки** — нумерация `[1..n]` в тексте ответа плюс блок «Источники».

### Настройки

* Выбор LLM: локальный каталог или DeepSeek.
* Выбор и скачивание embedding-модели.
* API-ключ DeepSeek (маскируется, хранится в локальной БД).
* Пресет генерации.
* Подпись версии в подвале настроек.

## Нефункциональные свойства

| Свойство | Как обеспечено |
|---|---|
| Офлайн | Всё, кроме первичного скачивания моделей и статей Википедии, локально |
| Приватность | Диалоги и факты — в локальной БД приложения; облачный режим включается явно |
| Устойчивость к обрывам сети | До 3 попыток скачивания, чистый старт без `resume`, атомарное появление файла |
| Честность состояний | `DownloadProgress.totalBytes == null` → проценты не рисуются, показываются МБ |
| Тестируемость | Чистые функции вынесены отдельно (`FactExtractor`, `QueryRouter`, `PromptBuilder`, `StructureChunker`, `EmbedMath`, `validateModelFile`) и покрыты юнит-тестами |
| Минимализм зависимостей | Ручной DI вместо Hilt, Ktor в common-коде вместо дублей `HttpURLConnection` |

## Что нужно перед первым запуском

* ~1.5 ГБ (Qwen2.5-1.5B-Q8) или ~331 МБ (Qwen3-0.6B-int4) — генеративная модель.
* ~157–165 МБ — EmbeddingGemma 270M.
* Стабильный интернет только на этапе скачивания.
* На Android — разрешение `INTERNET` (объявлено в манифесте, нужно только для скачивания).

Модели лежат в `filesDir/models/` на Android и в `./models/` на Desktop,
и скачиваются с HuggingFace, организации `litert-community`, без логина и API-ключа.
